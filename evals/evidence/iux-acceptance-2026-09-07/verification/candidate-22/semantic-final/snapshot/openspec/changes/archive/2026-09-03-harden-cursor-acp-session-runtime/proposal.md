## Why

Текущий MCP-мост уже запускает Cursor ACP, но его состояние зависит от polling,
не ограничивает жизненный цикл сессии и не гарантирует корректный scope рабочего
каталога. Из-за этого его нельзя надёжно использовать как долгоживущего
субагента для задач Codex с реальными изменениями.

## What Changes

- Добавить ожидание смены состояния сессии вместо неограниченного polling.
- Ввести управляемый жизненный цикл Cursor-процесса: таймауты, отмену,
  корректное завершение, лимиты и очистку сессий.
- Сделать состояние ходов и журнал событий адресуемыми и изолированными между
  последовательными запросами.
- Валидировать вход MCP на сервере и ограничить рабочие каталоги явно
  разрешёнными roots.
- Передавать Codex структурированный, ограниченный контекст запросов Cursor на
  вопрос, план и разрешение.
- Добавить fake-ACP интеграционные тесты для всех критических переходов.

## Capabilities

### New Capabilities

- `cursor-acp-session-runtime`: Надёжное, ограниченное и наблюдаемое выполнение интерактивных Cursor ACP-сессий.

### Modified Capabilities

- Нет.

## Impact

- Затрагивает `scripts/cursor-subagent-mcp.mjs`, MCP-схемы и тесты.
- Меняет контракт статуса сессии и добавляет инструменты ожидания/диагностики.
- Не меняет политику делегирования задачи высокого уровня; она будет отдельным change.
